# VALORANT 초기 흰색 프레임 실험 철회 및 회귀 복구

2026-10-09. 초기 흰색 프레임을 줄이기 위해 추가했던 숨겨진 창 사전 적용과 임시 Region은 실제 게임 회귀 때문에 철회했다. 이전의 최소화/복원 깜빡임 수정과 메이플 전용 Region·드래그 처리는 유지한다.

## 확인한 회귀 원인

`%TEMP%/Bald-frame-state-16380.jsonl`, 대상 PID 28220/HWND 2012ce:

- 18:21:34.488 최초 선택 시 visible=false, STYLE=04cf0000이었다.
- 임시 Region 설치가 반환한 18:21:34.887에는 게임이 표시되어 visible=true, STYLE=14cf0000이었다.
- BALD는 사전 적용 시작 때 읽어둔 숨김 상태의 STYLE에서 테두리 비트만 제거했다. 18:21:36.715 결과 STYLE=040b0000, visible=false가 되었다. 소유자가 그 사이 설정한 WS_VISIBLE(10000000)이 사라졌다.
- Region은 해제되어 종류 0으로 돌아왔지만 창 가시성은 돌아오지 않았다. 따라서 작업표시줄 미표시는 남은 Region만의 문제가 아니다.
- 흰 화면의 게임 렌더링 내부 원인은 로그만으로 확정하지 않는다. 이번 초기화 중 스타일/Region 변경이 표시 경합과 내용 영역 변화를 일으킨 사실은 확인했다.
- 마지막 로그에 HWND 폐기가 기록되어 있고, 조사 당시 VALORANT 프로세스는 없었다. Riot Client만 확인했다. 게임을 강제로 표시·종료·재실행하지 않았다.

## 철회한 변경

- 숨겨진 창 열거 및 표시 전 스타일 적용 제거.
- 일반 게임의 임시 Region 설치/복구와 그에 따른 DWM 복원 마커 제거.
- Watcher의 자동 적용을 기존 `enumerate_windows → make_borderless` 경로로 복귀.
- 이미 숨겨진 창과 최소화된 창을 변경하지 않는 기존 검사를 유지.
- 실험 구현만 검증하던 테스트는 제거. 숨겨진 초기 창의 STYLE/EXSTYLE/Region/내용 크기가 바뀌지 않고, 게임 소유자가 표시한 후에 정상 적용되는 회귀 테스트로 대체.
- Region 종류/경계와 client 좌표 진단 로그는 읽기 전용이므로 유지.

## 검증

- `cargo check`, `cargo fmt --check`, `git diff --check`: 통과.
- `cargo test -- --test-threads=1`: 56 통과, 0 실패, 6 제외.
- `cargo build`: 통과. `target/debug/bald.exe`를 새 코드로 갱신했다. 자동 실행하지 않았다.
- 메이플 드래그/복원/최소화, 일반 창 내용 크기 보존과 복원 등 기존 Win32 모사 창 검사 포함. 실제 VALORANT 재실행은 수행하지 않았다.

## 현재 상태

이번 실험 때문에 생긴 사전 적용 경로를 제거하고 기존 정상 코드 경로로 복구했다. 최초 실행의 원래 두꺼운 흰 프레임 문제는 미해결이다. 새 실행 파일로 BALD와 VALORANT를 다시 실행한 실제 화면 확인이 필요하다. 최초 표시를 앞당기려는 목적으로 렌더링 초기화 중 창을 다시 변경하지 않는다.
